# 04 — تصميم تجربة CLI (العرض المرتب + الاختيار)

## 1. متطلب المستخدم كما ورد حرفيًا

> "تعرض الأداة جودة الفيديوهات وتعرض الدبلجة المتوفرة بشكل مرتب، والمستخدم يختار الدبلجة ويختار الدقة، والأداة تحمّل الفيديو بالدبلجة والجودة المختارة. عند تشغيل الأداة تطلب الرابط ثم تقوم بالعملية."

**التدفق المطلوب (4 خطوات فقط):**

```
[1] أدخل رابط الفيديو  →  تحقق من الرابط
[2] جدول الدبلجات       →  المستخدم يختار رقمًا
[3] جدول الجودات        →  المستخدم يختار رقمًا
[4] تحميل + شريط تقدم  →  رسالة نجاح مع المسار واللغة والجودة
```

أي خطوة إضافية (تسجيل دخول، إعدادات معقدة) تُخفى خلف `--advanced` ولا تظهر في الوضع العادي.

## 2. المكدّس المقترح للواجهة

| الحاجة | المكتبة | لماذا هذه؟ |
|---|---|---|
| جداول ملونة + تقدم + رسائل | **`rich`** (57k+ نجمة، توثيق ممتاز) | `Table`, `Progress`, `Console.status`, `Prompt` — المعيار لواجهات بايثون الجميلة |
| أوامر وخيارات (`--quality`, `--lang`) | **`click`** أو **`rich-click`** | `click` معيار الأوامر؛ `rich-click` يغلّفه بمظهر `rich` تلقائيًا |
| اختيار تفاعلي بالأسهم | **`questionary`** (أو `inquirer`) | أفضل من إدخال أرقام يدويًا؛ يدعم العربية ويمنع إدخالًا خاطئًا |
| تحقق من الروابط | `urllib.parse` + تعبير بسيط | لا مكتبة خارجية — يكفي فحص `youtube.com/watch`, `youtu.be/`, `music.youtube.com` |

التثبيت:

```bash
pip install rich click rich-click questionary yt-dlp
```

> بديل خفيف: `argparse` من المكتبة القياسية + `rich` للعرض فقط — مقبول لـ MVP إن أردت صفر اعتماديات زائدة.

## 3. شكل العرض المرتب (مواصفة دقيقة)

### جدول معلومات الفيديو (سطر واحد غني)

```
╭─ 🎬 عنوان الفيديو ─────────────────╮
│ القناة • المدة 12:34 • المشاهدات   │
╰────────────────────────────────────╯
```

### جدول الدبلجات — الأعمدة الإلزامية

| # | اللغة | الاسم المعروض | النوع | الجودة الصوتية |
|---|---|---|---|---|
| 1 | `ar` | العربية | أصلي ✅ | 128k |
| 2 | `en` | English | مدبلج | 128k |
| 3 | `es` | Español (auto) | تلقائي 🤖 | 64k |

- رتّب: الأصلي أولًا (`audioIsDefault`)، ثم المدبلج البشري، ثم التلقائي، ثم الوصفي (`descriptive` — ضعه أخيرًا أو أخفه بخيار).
- إذا لغة واحدة فقط: اعرض "لغة واحدة (الأصلية: ar)" وتجاوز الاختيار.
- استخدم أكواد `ISO 639-1` (`ar/en/es`) مع الاسم الكامل ثنائي اللغة.

### جدول الجودات — الأعمدة الإلزامية

| # | الدقة | FPS | الكودك | الحجم التقريبي | ملاحظة |
|---|---|---|---|---|---|
| 1 | 2160p 4K | 60 | av01 | 1.2GB | يحتاج مشغّلًا حديثًا |
| 2 | 1080p | 60 | avc1 (H264) ✅ | 380MB | الأفضل توافقًا |
| 3 | 720p | 30 | avc1 | 150MB | خفيف |
| 4 | 480p | 30 | avc1 | 80MB | — |
| 5 | صوت فقط | — | m4a | 12MB | — |

- وحّد التكرارات: اعرض أعلى `tbrabr` لكل `height` بدل إغراق المستخدم بعشرات `format_id`.
- ضع علامة ✅ على "الموصى به" (`1080p h264` عادة).
- اعرض الحجم بـ `filesize/filesize_approx` مع `~` عند التقريبي.

### شريط التقدم

استخدم `rich.progress.Progress` مع أعمدة: `النسبة % • الحجم • السرعة • الوقت المتبقي`. اربطه بـ `progress_hooks` في `yt-dlp`:

```python
def hook(d):
    if d["status"] == "downloading":
        task.update(completed=d.get("downloaded_bytes") or 0)
```

## 4. سلوكيات UX إلزامية (تعريف "عمل احترافي")

1. **تحقق فوري من الرابط** مع رسالة خطأ عربية واضحة، ودعم `youtu.be` القصيرة وقوائم التشغيل (ارفض القوائم برسالة أو ادعم `--playlist` صريحًا).
2. **حالة تحميل (spinner)** أثناء جلب البيانات: `with console.status("🔍 جارٍ فحص الدبلجات...")`.
3. **اختيار افتراضي ذكي**: Enter بدون إدخال = الأصلي + 1080p. لا تجبر المستخدم على كتابة أرقام إن كان مستعجلًا.
4. **وضع غير تفاعلي** للأتمتة: `--url URL --lang ar --height 1080 --yes` يتجاوز كل الأسئلة.
5. **رسائل خطأ عربية + حل**: "تعذّر العثور على ffmpeg — ثبّته من https://ffmpeg.org/download.html ثم أعد التشغيل" بدل `traceback` خام. استخدم `rich.traceback` للمطورين فقط مع `--verbose`.
6. **دعم RTL**: العربية تُعرض صحيحة في `rich`، لكن الأرقام والأكواد (`ar`, `1080p`) تُترك LTR — لا تعكسها.
