# 01 — كيف يخزّن يوتيوب الدبلجة؟ (آلية Multi-Audio Tracks)

## 1. الفكرة الجوهرية في سطر واحد

يوتيوب لا يرفع "نسخة مدبلجة" كفيديو مستقل في القنوات الاحترافية، بل يرفع **فيديو واحد + عدة مسارات صوتية (audio tracks)**، كل مسار لغة/دبلجة. المشغّل يبدّل بينها بزر الإعدادات. أداتنا ستفعل نفس الشيء: **نسرد المسارات، والمستخدم يختار واحدًا، ثم ندمجه مع الفيديو.**

> لا تخلط بين: **الدبلجة (dubbed audio track)** و**الترجمة (subtitle/caption)** و**العنوان/الوصف المترجم**. نحن نتعامل مع الأولى فقط.

## 2. أين توجد معلومة الدبلجة تقنيًا؟

عندما يطلب `yt-dlp` بيانات الفيديو من `streamingData.adaptiveFormats`، كل صيغة صوتية تحمل كائنًا اسمه `audioTrack`:

```json
"audioTrack": {
  "id": "es.dubbed-auto",
  "displayName": "Spanish (Latin America) - dubbed (auto)",
  "audioIsDefault": false
}
```

وكود مستخرج يوتيوب في `yt-dlp` (`yt_dlp/extractor/youtube/_video.py`) يحوّل هذا إلى:

| الحقل في `yt-dlp` | المصدر | مثال |
|---|---|---|
| `language` | `audioTrack.id` مقسومًا على `.` (الجزء الأول) | `es` من `es.dubbed-auto` |
| `audioIsDefault` | هل هذه لغة الأصل؟ | `true` للغة الأصلية |
| `displayName` | اسم العرض + كشف الوصفية/الأصلية | `original`, `descriptive` |
| `format_note` | يُبنى منها نص مثل `dubbed-auto`, `original` | يظهر في `-F` |

**القاعدة العملية للأداة:**
- `language` مثل `ar`, `en`, `es`, `fr` هو المعرّف الموثوق للفلترة.
- `displayName` للعرض البشري المرتب (مثال: "الإسبانية — مدبلجة تلقائيًا").
- `audioIsDefault == True` غالبًا = اللغة الأصلية للفيديو.

## 3. أنواع البث التي ستصادفها

| النوع | الوصف | علاقته بالدبلجة |
|---|---|---|
| **Progressive** | ملف واحد فيه فيديو+صوت (itag قديم مثل 18/22) | جودة ≤720p، لغة واحدة فقط — **غير صالح للدبلجة** |
| **DASH (adaptiveFormats)** | فيديو منفصل + صوت منفصل بجودات متعددة | **المصدر الأساسي** — كل دبلجة ملف صوتي مستقل |
| **HLS (m3u8)** | قوائم تشغيل للبث، تظهر مع عميل `web_safari` | بديل عند حجب DASH، يحتاج `ffmpeg` أو `m3u8` downloader |
| **SABR** | بروتوكول البث الجديد ليوتيوب (server-side adaptive) | يظهر مع عميل `web` — يحتاج PO Token أحيانًا |

**النتيجة:** الأداة يجب أن تتعامل حصرًا مع **DASH/HLS المنفصلة + دمج**، لا مع Progressive.

## 4. ماذا يعني أن الفيديو "فيه دبلجة"؟

- فيديو **بدون دبلجة**: كل الصيغ الصوتية لها نفس `language` (مثلًا `en` فقط).
- فيديو **مدبلج من القناة**: ستجد `language` متعددة حقيقية (`en`, `ar`, `es`...) مع `displayName` نظيف.
- فيديو **مدبلج آليًا (auto-dub)**: ستجد لاحقات مثل `.dubbed-auto` في الـ `id`. جودتها متغيرة ويجب وسمها في العرض بـ "(تلقائية)".

## 5. حدود مهمة اكتشفها البحث

1. **ليست كل الفيديوهات فيها دبلجة.** الغالبية لغة واحدة. الأداة يجب أن تعرض "لا توجد دبلجة — اللغة الأصلية فقط" بدل أن تفشل.
2. **الدبلجة التلقائية قد لا تظهر لكل العملاء (`player_client`).** عميل `android`/`ios`/`mweb` قد يعطي مسارات أكثر أو أقل من `web`. الحل: تجربة عميل بديل عند غياب المسارات (انظر ملف 02).
3. **بعض المسارات `descriptive` (وصف صوتي للمكفوفين).** يجب تمييزها وعدم تقديمها كدبلجة عادية — الكود المصدري يعطيها أولوية `-10`.
4. **الجودة العالية (>1080p) قد تكون VP9/AV1** وتحتاج مشغّلًا حديثًا. فضّل `h264` للتوافق إلا إذا طلب المستخدم غير ذلك.

## 6. التوصية العملية للأداة

- اعتمد حقل `language` للفلترة البرمجية، وحقل `displayName`/`format_note` للعرض.
- اعرض جدول الدبلجات بهذه الأعمدة: `# | اللغة (كود) | الاسم المعروض | أصلي/مدبلج/تلقائي | افتراضي؟ | متوسط البتريت`.
- إذا وُجدت لغة واحدة فقط → تخطَّ خطوة اختيار الدبلجة تلقائيًا وانتقل لاختيار الجودة.
- خزّن `language` المختارة لتمريرها في `format` (التفاصيل في ملف 02).
